# ADR-0001: Modular monolith with durable workers

**Status:** Accepted

## Context
The brief suggests separate `apps/api`, `workers/agent-worker`, `workers/workflow-worker` and several
`packages/*`. Agents, workflows and the API all need the same domain model, DB access, policies and
providers.

## Decision
One Python package `companyos` (in `apps/api`) contains API, services, domain models, agent runtime,
tool gateway and Temporal workflows/activities. Two entrypoints run from it:
`uvicorn companyos.main:app` (API) and `python -m companyos.worker` (Temporal worker).
The worker hosts both workflows and agent activities on one task queue in V1; splitting into an
agent queue and a workflow queue is a configuration change (`TEMPORAL_TASK_QUEUE`) later.
`packages/` is not created until a second consumer exists (no empty abstractions). Shared TypeScript
types live in `apps/web/src/lib/api-types.ts`, generated by hand from Pydantic schemas in V1.

## Consequences
+ No duplicated domain code, no network hops between "services", simple local dev.
+ Clean module boundaries (`services`, `agents`, `tools`, `workflows`, `providers`) allow extraction later.
- API and worker images share dependencies (slightly larger API image).
